# Lightweight Visual Editor Plan (Custom Implementation)

Since you only need a visual interface to edit settings, order sections, and pick colors/images, a full Headless CMS like Strapi is overkill (it requires a database, separate server, and API integration).

Instead, we can build a **Custom Theme Editor** directly into your Express app.

## 1. Architecture

- **No Database**: The "database" is your `views/config/*.json` files.
- **No API Sync**: The editor reads/writes files directly.
- **Schema Driven**: The editor parses the `{% schema %}` tags in your `.psp` files to generate the UI.

## 2. Proposed Solution: `json-editor` Integration

We will use the open-source library **@json-editor/json-editor** to automatically generate forms from your schemas.

### A. New Routes (`server/editor.js`)

1.  `GET /editor`:
    - Reads `views/config/header.json` (and others).
    - Parses all `views/sections/*.psp` to extract the JSON schemas.
    - Merges them into a master JSON Schema.
    - Renders the Editor UI.
2.  `POST /editor/save`:
    - Receives the updated JSON payload.
    - Writes it back to `views/config/header.json`.

### B. The Editor UI (`views/editor.psp`)

A simple page containing:

- **Sidebar**: List of sections (draggable for reordering).
- **Main Area**: The Form generated by `json-editor`.
  - If schema says `"type": "color"`, it shows a Color Picker.
  - If schema says `"type": "image"`, it shows an Image Input.
- **Preview**: An iframe showing the site (auto-refreshes on save).

## 3. Implementation Steps

### Step 1: Install Dependencies

```bash
npm install body-parser
```

_(We don't need heavy packages, just a way to parse POST requests)_

### Step 2: Create the Schema Parser

We need a helper function in `server/utils.js` that:

1.  Reads a `.psp` file.
2.  Extracts the text between `{% schema %}` and `{% endschema %}`.
3.  Parses it as JSON.

### Step 3: Build the Editor Route

```javascript
app.get("/editor", (req, res) => {
  // 1. Get current config
  const headerConfig = require("../views/config/header.json");

  // 2. Get available sections & their schemas
  const sections = {};
  fs.readdirSync(sectionsDir).forEach((file) => {
    const schema = extractSchema(file); // Helper function
    sections[schema.name] = schema;
  });

  res.render("editor", { config: headerConfig, schemas: sections });
});
```

### Step 4: The Frontend (HTML/JS)

Use `json-editor` to render the form.

```html
<div id="editor_holder"></div>
<script src="https://cdn.jsdelivr.net/npm/@json-editor/json-editor@latest/dist/jsoneditor.min.js"></script>
<script>
  const editor = new JSONEditor(document.getElementById("editor_holder"), {
    schema: {
      type: "object",
      properties: {
        sections: {
          type: "array",
          format: "tabs",
          items: {
            // Dynamic schema based on selected section type
          },
        },
      },
    },
  });
</script>
```

## 4. Why this is better than Strapi

1.  **Lightweight**: Adds ~0ms overhead to your production site.
2.  **Native**: It understands your specific `{% schema %}` format perfectly.
3.  **Version Control**: Since it saves to JSON files, all your layout changes are committed to Git. Strapi stores data in a DB, which is harder to version control.
